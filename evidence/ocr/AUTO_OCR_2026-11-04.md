# 提供 PDF → 自动 OCR 验证

日期：2026-11-04
目标：事件页面提供的可下载 PDF 不再需要人工点“解析”，补全后直接自动 OCR。

## 实现

- 补全任务 `event.enrich` 完成后，检查该事件的 `documents[]`：
  - `status=downloadable`
  - 扩展名为 PDF/PNG/JPEG/WebP/TIFF
  - 尚未解析（无 parseProvider/parsedAt）
  - 还没有同名 material
- 满足条件的文档自动入队 `document.parse`（默认每事件最多 3 份，`AUTO_OCR_MAX_DOCS`）
- `AUTO_OCR_DOCUMENTS=0` 可整体关闭
- 解析链路：文本层 PDF → pdftotext；扫描/复杂/有重要图片 + MinerU token → MinerU vlm；
  否则视觉 OCR 兜底
- OCR 结果进入事件 `materials[]`，并自动触发 `event.agent-report`

## 实测

隔离 demo（视觉 OCR，无 MinerU token）：

1. PATCH 事件加入 `http://127.0.0.1:8899/scan.pdf`（扫描件，downloadable）
2. 触发 `event.enrich`
3. 补全完成后自动出现 `document.parse` 任务，`payload.auto=true`
4. 任务成功：`provider=vision-ocr`，`pages=1`，`chars=61`
5. 事件材料新增：
   - webpage（图文页 OCR，47 字符）
   - document（自动 OCR 名单，61 字符）
6. 文档字段补齐 `parseProvider/parsedAt/chars`，并自动排队 Agent 材料报告

结果：无需人工点解析，PDF 自动进入材料清单。

## 与 MCP 方案对比

| 方案 | 行为 |
|---|---|
| **自动 OCR（当前默认）** | 事件补全发现 downloadable PDF → 直接排队 OCR；有成本上限、可关闭 |
| MCP 工具（可选，未启用） | Agent 自主决定何时解析扫描件/指定 PDF；适合非事件文档或复杂判断 |

当前直接 OCR 已满足“提供的 PDF 直接 OCR”；Agent 仍会读取 OCR 材料并整理汇报。
