# 图片漏识修复验证（网页内嵌图片 + PDF 内嵌图片）

日期：2026-11-04
问题：用户反馈“部分图片未识取到”。

## 原因

1. 网页截图 OCR 只在 **Playwright 渲染后文字仍 <300 字符**时触发；页面文字够多时，
   内嵌在图片里的文字（展商名单、展位图等）完全不会 OCR。
2. 截图只截当前页面状态，懒加载图片/轮播图可能没加载或不在截图范围内。
3. PDF 有文本层时直接走 `pdftotext`，PDF 内的大图（名单截图/展馆图）里的文字丢失。

## 修复

### 网页
- 浏览器渲染前自动滚动页面，触发懒加载。
- 当页面文字 < 4000 字符且含 `<img>` 时，进入浏览器渲染；
  逐个对**尺寸足够大的内嵌图片**做元素截图并 OCR（默认最多 2 张：
  `OCR_MAX_EMBEDDED_IMAGES`），把 OCR 文本追加到页面文本。
- 若页面文字很多但确实需要图片 OCR，可设 `OCR_WEB_IMAGES_ALWAYS=1` 强制渲染并识别图片。
- 结果 `engine=ocr-images`，`ocr.method=embedded-images`。

### PDF
- 先 `pdfimages -list` 检测 PDF 内嵌图片尺寸；大图（面积 ≥200k 或 ≥400×250）视为重要图片。
- 文本层 PDF + 重要图片 + MinerU token → 走 **MinerU vlm**（`method=mineru-batch+images`），
  文字层和图片内容一起解析。
- 无 MinerU / MinerU 失败 + 视觉 OCR → 提取重要图片逐张 OCR，
  拼到 `pdftotext` 文本后（`provider=pdftotext+vision-images`）。
- 纯文本 PDF 仍走 pdftotext，不增加成本。

## 实测结果

| 场景 | 结果 |
|---|---|
| 图文网页（正文 480 字符 + 2 张 900px 图片） | `engine=ocr-images`，`ocr.images=2`，OCR 文本追加成功 |
| 文本层 PDF + 内嵌 1200×340 名单截图，走 MinerU token | `provider=mineru-vlm`，`method=mineru-batch+images`，103 字符，文本层与图片文字都在 |
| 文本层 PDF + 内嵌图片，视觉 OCR 兜底 | `provider=pdftotext+vision-images`，图片文字追加到文本层后 |
| 测试 | `tests/collector-ocr.test.mjs`、`tests/ocr-pdf-images.test.mjs`；全量 272/272 |

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `OCR_MAX_EMBEDDED_IMAGES` | 2 | 每个网页最多 OCR 的内嵌图片数 |
| `OCR_WEB_IMAGES_TEXT_LIMIT` | 4000 | 页面文字低于此值且有图片时触发图片 OCR |
| `OCR_WEB_IMAGES_ALWAYS` | 0 | 设为 1 时不论文字多少都识别内嵌图片 |
| `OCR_MAX_PDF_IMAGES` | 3 | 文本层 PDF 内嵌图片最多 OCR 张数 |
