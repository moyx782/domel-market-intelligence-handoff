# Additive source collection

Updated 2026-10-28. No default sources have been chosen for the team.

## Inputs and collection

Every fresh collect/research run attempts automatic search, including when the
project has source URLs. The candidate pools are:
1. Project URLs (including user preferences copied into the project).
2. `SOURCE_DEFAULT_URLS`, a JSON array of team-selected page URLs; currently `[]`.
3. URLs discovered by web search, without site filters by default.

Canonical URLs (including removal of fragments) are deduplicated across pools.
Each pool rotates between domains, then collection rotates between pools. Thus a
long manual/default list does not crowd out the discovered pool. Five unique
pages maximum and the existing execution time budget still apply. This makes a
broader set eligible; it does not guarantee five successful pages or complete
coverage. Search/fetch failures and pages excluded by the cap remain visible in
coverage notices. Search failure does not discard supplied/default pages.

Saved-source extraction is different: it only reads stored source text and does
not search, fetch, insert default sources, or change retrieval timestamps.

## Configuration and migration

```dotenv
SOURCE_DEFAULT_URLS=[]
SOURCE_RESTRICT_DOMAINS=
```

`SOURCE_ALLOWED_DOMAINS` is retired and ignored, even if an old `.env.host` still
contains `www.ebmpapst.com`. Remove that legacy line to avoid confusion. The new
`SOURCE_RESTRICT_DOMAINS` is an optional explicit administrator restriction, not a
team preference list. Leave it blank for public HTTPS discovery and collection.
If deliberately configured, both search and retrieval respect those restrictions.
Future default URLs do not automatically become domain restrictions.

Only HTTPS pages without credentials or nonstandard ports are eligible. IP
literals and local/reserved hostnames are rejected. Host collection uses provider
Fetch, not host-network crawling. The legacy Edge native-fetch fallback also
checks resolved DNS addresses before each request and redirect. Its DNS check
is defense in depth, not a DNS-pinning or network-egress firewall guarantee.

Pull the updated code, restart API and Worker, and refresh the frontend. No schema
migration, new credential or change to existing evidence is needed. If using the
legacy Edge endpoint, redeploy its updated function too; the dashboard bundle is
regenerated by `node scripts/bundle-research.mjs`.

## Acceptance

- With defaults empty, a new project containing a supplied URL still calls search.
- Search queries contain no `site:` filter when restrictions are empty.
- Multiple public domains are eligible, and found pages enter collection alongside
  supplied/default URLs within the five-page cap.
- The same URL supplied in multiple pools is fetched once; fragments do not
  create another source.
- Search failure still allows explicit/default retrieval and marks coverage partial.
- Saved-source extraction does not initiate search or new retrieval.

Tests use injected provider responses and example URLs. These examples are not
selected defaults and do not constitute a live paid-provider acceptance run.
Existing runs are historical; create a fresh project to test the changed flow.
